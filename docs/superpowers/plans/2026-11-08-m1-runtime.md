# M1 Runtime Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for this approved milestone. Implement
> tasks in order and keep a progress ledger. The owner authorized execution, not another approval
> round. Keep the current checkout and branch.

**Goal:** Deliver a reproducible Rust API/Worker foundation and real Compose integration environment.

**Architecture:** Two binaries share configuration, PostgreSQL, HTTP health, and lifecycle code.
Migration is an explicit API subcommand; API/Worker startup never runs migrations automatically.
OpenAPI is generated from Rust response types and consumed by generated TypeScript definitions.

**Spec:** [Approved product design](../specs/2026-11-08-complete-product-design.md) and
[M1 milestone](./2026-11-08-product-milestones.md#m1-runtime-contracts-and-reproducible-environment).

**Tech stack:** Rust 1.98, Axum 0.8, SQLx 0.9, Tokio, Utoipa, PostgreSQL 18, Valkey 9,
Centrifugo 6, SeaweedFS 4, Caddy 2, React, and pnpm. Pin exact compatible releases in executable files.

## Global constraints

- Put Rust at the repository root and retain `web/`.
- Follow all global readability requirements: semantic blank lines, clear names, English comments,
  documented public functions, at most three nesting levels, and at most 100 characters per line.
- Do not introduce account/message tables, fake connected UI, business jobs, or optional mail/calls.
- Preserve the existing frontend and use its Prettier configuration.
- Never log database URLs, passwords, cookies, query strings, or arbitrary incoming request headers.
- Use real PostgreSQL for migration/readiness checks and real Compose services for acceptance.
- No publication, push, or deployment beyond the isolated local acceptance environment.

## Review focus

- A dead database must fail readiness without killing liveness; cover in Task 2.
- Concurrent migrators must apply a non-idempotent migration once; cover in Task 2.
- A malformed secret-bearing configuration or request must not leak into logs/errors; cover Tasks 1-2.
- Optional services must not become hidden API dependencies; cover Task 3 acceptance.
- A gateway restart must preserve database and private object storage; cover Task 3 acceptance.

## Task 1: Configuration and runtime contracts

**Files:** `Cargo.toml`, `src/lib.rs`, `src/config.rs`, `tests/configuration.rs`, `.gitignore`.

**Interfaces:** `ServiceKind::{Api, Worker}`; `Settings::from_values(values, service)` returning
validated settings or a safe configuration error; `Settings::from_env(service)` for binaries.
Settings contain the database connection options, bind address, pool budget, and safe log level.

- [ ] Write behavior tests for missing/malformed database configuration, bounded pool settings,
      invalid bind addresses, independent service ports, and credential-safe diagnostics.
- [ ] Run `cargo test --test configuration`; observe failure before implementing validation.
- [ ] Implement strict environment parsing without global environment mutation in tests. Use named
      option structs and redacted Debug output for secret-bearing settings.
- [ ] Run configuration tests, Rustfmt, and Clippy; commit the independently usable boundary.

## Task 2: HTTP, PostgreSQL, migrations, and process lifecycle

**Files:** `src/http.rs`, `src/runtime.rs`, `src/telemetry.rs`,
`src/infrastructure/mod.rs`, `src/infrastructure/postgres.rs`, `src/bin/api.rs`,
`src/bin/worker.rs`, `migrations/README.md`, `tests/runtime.rs`, and migration test fixtures.

**Interfaces:** `postgres::connect_pool(settings) -> PgPool`; migration runner accepting a pool and
resolved SQLx migrator; `http::router(state) -> Router`; `runtime::serve(settings, service)`;
API commands `serve`, `migrate`, and `openapi`; Worker serves its internal health listener.
`GET /health/live` returns process health; `GET /health/ready` requires DB connectivity and the
embedded migration catalogue. Failures use a typed error envelope with a generated request ID.

- [ ] Add tests for HTTP liveness while the DB is unreachable, correlated sanitized errors, and
      readiness before/after migration. Verify missing behavior fails before implementing it.
- [ ] Implement bounded PostgreSQL acquisition/checks, explicit SQLx locked migrations, health
      routes, request IDs, and structured application-only logging without request/SQL secrets.
- [ ] Add real-DB tests with isolated databases and non-idempotent test migrations for concurrent
      migrators, persisted data, failed migrations, and readiness after database shutdown.
- [ ] Implement separate API/Worker processes with bounded signal-driven shutdown. Integration
      acceptance sends termination signals and verifies exit rather than testing signal internals.
- [ ] Export an OpenAPI document without requiring a database or application secrets.
- [ ] Run Rust checks and all runtime/configuration tests, then commit this behavior.

The production migration catalogue starts empty. SQLx creates its own migration metadata; business
migrations begin when M2 owns them. Test-only DDL proves migration atomicity and serialization.

## Task 3: Compose, private storage, and integrated acceptance

**Files:** `compose.yaml`, `deploy/Dockerfile`, `deploy/Caddyfile`,
`deploy/centrifugo.json`, SeaweedFS configuration, `.env.example`, `.dockerignore`,
and `scripts/check-runtime.sh` with focused acceptance helpers if needed.

**Interfaces:** Same-origin gateway routes health/API to Rust and WebSocket to Centrifugo, with
frontend fallback only for frontend routes. PostgreSQL/Valkey and service administration ports stay
private. S3 has a distinct browser endpoint, credentials, and a persistent filer/object volume.

- [ ] Package API/Worker in one image, serve the built frontend through Caddy, and make migration an
      explicit one-shot Compose service required by API/Worker readiness.
- [ ] Configure pinned PostgreSQL, Valkey, authenticated Centrifugo, and private SeaweedFS. Use
      required runtime credentials rather than usable checked-in secrets. Disable unrelated services.
- [ ] Add an acceptance runner with an isolated project name, safe local credentials, bounded
      startup, and cleanup restricted to resources it created. Validate health and private service
      boundaries through real network requests, including unauthenticated S3 rejection.
- [ ] Verify PostgreSQL outage/recovery, two migrators, API/Worker graceful restart, gateway routing,
      and persistence of a test-only database record and signed S3 object across restarts.
- [ ] Run image builds and Compose acceptance; fix observed integration failures and commit.

## Task 4: Frontend contracts, CI, and operations documentation

**Files:** `openapi/api.json`, `web/src/api/schema.d.ts`, API type-generation scripts,
`web/package.json`, `web/pnpm-lock.yaml`, `.github/workflows/backend.yml`, root README,
`docs/development.md`, and `docs/operations.md`.

**Interfaces:** Rust OpenAPI export is the source of truth; a repeatable generator produces checked-in
TypeScript definitions. CI detects drift by regenerating both artifacts and comparing them.

- [ ] Add OpenAPI type generation and contract-drift checking without changing frontend behavior.
- [ ] Add backend formatting/lint/test CI, real PostgreSQL integration, and Compose acceptance.
      Keep existing frontend CI and verify frontend build/tests/formatting locally.
- [ ] Document secret creation, clean startup, explicit migration, health semantics, storage volumes,
      safe shutdown, dependency failures, and the limits of the M1 local environment.
- [ ] Run final checks and a fresh-context whole-change review. Fix important findings with focused
      regression coverage, update milestone status only from observed results, and commit.

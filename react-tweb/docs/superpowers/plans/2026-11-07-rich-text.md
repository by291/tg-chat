# Telegram Rich Text Implementation Plan

**Goal:** Preserve Telegram-style inline formatting and structured message content throughout
composition, drafts, sending, editing, forwarding, and display, without an AI entry point.

**Architecture:** Keep Lexical and the existing custom emoji nodes. Store sanitized, semantic HTML
in an optional `richText` field alongside searchable plain text and UTF-16 custom emoji ranges.
HTML is an interchange format, not executable content or a persisted Lexical snapshot. Render
through a restrictive sanitizer and React components for emoji, spoilers, dates, and formulas.

**Tech stack:** React, Lexical official extensions, Ark UI, CSS Modules, DOMPurify,
html-react-parser, and KaTeX. Preserve existing plain messages and database compatibility.

## Work units

- [x] Message content: add optional richText and draftRichText; preserve content through all
      message actions; sanitize HTML and render formatting, blocks, emoji, spoilers, and formulas.
- [x] Editor integration: replace PlainTextPlugin with RichTextPlugin, register list/table/link/code
      and custom nodes, import/export semantic HTML, preserve selection and custom emoji ranges.
- [x] Controls: selection toolbar, formatting shortcuts, link/date/formula dialogs, undo/redo,
      expanded block controls for headings, lists, quotes/details, tables, code, and dividers.
- [x] Verification: round-trip mixed formatting and emoji; validate unsafe HTML/links; exercise
      partial selections, draft restoration, edit/forward preservation, IME and newline behavior.
- [x] Inspect real Telegram and local UI, run targeted tests, TypeScript/build, formatting, and
      review the final diff. Leave changes uncommitted until requested.

## Review focus

- Menus and dialogs must retain the original text selection and return focus safely.
- Formatting-only edits must be detected even when the plain text is unchanged.
- Malicious pasted HTML and links must never become executable message content.
- Paragraph, table, and list separators must remain reflected in plain-text emoji offsets.
- Existing emoji playback, resize animation, message anchoring, and old drafts must continue working.
